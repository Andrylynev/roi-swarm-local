# ROI Swarm Local

Локальный рой для Windows и Linux: отдельные модели для маршрутизации, планирования,
воркеров и итогового ответа, Hermes-инструменты для работы с файлами и командами,
OpenAI-совместимый API и веб-панель. Облачный провайдер и его ключи не нужны.
**Docker не используется.** Модели исполняются нативным Prism llama.cpp, а не Python-прокси
поверх облачного API.

Это отдельная установка: она не меняет существующие Hermes-профили, облачный ROI Swarm
или системный Python. Веса скачиваются с Hugging Face; в GitHub их нет.

## Установка одной командой

Запускайте от обычного пользователя. **Не используйте root, sudo или «Запуск от имени
администратора».** Установщик откажется работать с повышенными правами и не устанавливает
дистрибутивные пакеты, драйверы, службы systemd или задания автозапуска.

Перед началом:

- **Windows 10/11 x64:** установленный [Git for Windows](https://git-scm.com/download/win)
  в `PATH`, нативный Windows PowerShell 5.1+ или PowerShell 7. После установки Git откройте
  новый PowerShell. WSL не нужен.
- **Linux x86_64:** Bash, `git`, `curl`; CPU-сборка runtime рассчитана на Ubuntu 24.04.
  Другие дистрибутивы могут требовать совместимых системных библиотек. Установщик их не меняет.
- Интернет к GitHub, Hugging Face и источникам Python/uv. На первом запуске загружаются
  приложение, отдельный Hermes, runtime и несколько гигабайт весов.
- Для CUDA: уже работающий NVIDIA-драйвер, видимый через `nvidia-smi`.
  Установщик не устанавливает драйвер. AMD/Intel GPU, macOS и ARM пока не являются
  поддерживаемыми путями этого bootstrap.

### Linux

```bash
curl -fsSL https://raw.githubusercontent.com/Andrylynev/roi-swarm-local/main/install.sh | bash
```

По умолчанию всё находится в `~/.roi-swarm-local`. Пример с другим диском и CPU:

```bash
curl -fsSL https://raw.githubusercontent.com/Andrylynev/roi-swarm-local/main/install.sh | bash -s -- --dir "$HOME/Local AI/roi-swarm" --backend cpu --profile fast --non-interactive
```

### Windows — обычный PowerShell

```powershell
irm https://raw.githubusercontent.com/Andrylynev/roi-swarm-local/main/install.ps1 | iex
```

По умолчанию используется `$HOME/roi-swarm-local`. Для установки на D: с пробелами в пути:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Andrylynev/roi-swarm-local/main/install.ps1))) -Dir 'D:\Local AI\roi-swarm' -Backend auto -Profile balanced -NonInteractive
```

`curl | bash` и `irm | iex` исполняют загруженный код. Если это неприемлемо для вашей
политики безопасности, сначала скачайте скрипт, прочитайте его и запустите локально.
URL ветки `main` меняется при обновлениях; для воспроизводимой установки закрепляйте
проверенную ревизию скрипта и репозитория самостоятельно.

### Параметры

| Bash / общая форма | PowerShell | Назначение |
| --- | --- | --- |
| `--dir PATH` | `-Dir PATH` | Новый пустой абсолютный каталог; пробелы поддерживаются |
| `--backend auto` | `-Backend auto` | CUDA при обнаруженном NVIDIA GPU, иначе CPU |
| `--backend cuda` | `-Backend cuda` | Требовать CUDA; ошибка вместо скрытого CPU fallback |
| `--backend cpu` | `-Backend cpu` | Явно CPU, без GPU-offload |
| `--profile balanced` | `-Profile balanced` | Bonsai 4B для воркеров, 9B для старших ролей |
| `--profile fast` | `-Profile fast` | Bonsai 2B для воркеров; 9B для старших ролей остаётся |
| `--with-security` | `-WithSecurity` | Дополнительно скачать WhiteRabbitNeo для текстовых консультаций |
| `--accept-whiterabbitneo-terms` | `-AcceptWhiteRabbitNeoTerms` | Подтвердить ознакомление с дополнительными условиями WhiteRabbitNeo |
| `--no-start` | `-NoStart` | Подготовить установку, но не запускать сервисы |
| `--non-interactive` | `-NonInteractive` | Не задавать вопросов; это не обход проверок безопасности |
| `--help` | `-Help` | Справка без загрузок и изменений |

Форма `--...` также принимается PowerShell-скриптом. Параметров для облачных ключей нет.
`--with-security` означает дополнительную **модель**, а не включение авторизации API.
Для неё также нужен `--accept-whiterabbitneo-terms` после ознакомления с
[условиями автора](https://huggingface.co/WhiteRabbitNeo/WhiteRabbitNeo-2.5-Qwen-2.5-Coder-7B/blob/4e7be6e25ccb4824f1dcce51c967e3e4e6e8d4e0/README.md).
Само подтверждение не является юридической гарантией совместимости вашего применения.

## Что устанавливается

В выбранном каталоге находятся исходники приложения, `.venv` Python 3.11,
`tools/` с управляемыми компонентами, `runtime/`, `models/`, `download/`, `cache/`,
отдельный `hermes/`, локальные настройки и данные. Если uv отсутствует, он устанавливается
внутри этого каталога без изменения глобального `PATH`. Python/uv-кэш также направляются
внутрь установки. Окружение приложения создаётся командой
`uv sync --frozen --python 3.11`, без тяжёлого optional extra `embeddings`.

Setup загружает закреплённые версии runtime/моделей с проверкой размера и SHA-256,
создаёт локальные конфигурации и отдельное окружение Hermes. Эти загрузки не являются
изменением весов или обучением модели. Конкретные URL, ревизии, размеры и хеши находятся
в [`local/assets.json`](local/assets.json); лицензии — в [THIRD_PARTY.md](THIRD_PARTY.md).

Повтор той же команды в том же каталоге:

1. Проверяет маркер `.roi-swarm-local-install`, путь и точный HTTPS origin публичного репозитория.
   Существующий чужой каталог, symlink/junction или неподтверждённый checkout отвергается.
2. Вызывает существующий `.venv` Python с `-m local.manage stop` **до** обновления кода и зависимостей.
   Неполная остановка блокирует продолжение. Чужие процессы не убиваются по номеру порта.
3. Обновляет только fast-forward (`fetch` и `merge --ff-only`), без `reset`, `clean` и `stash`.
   Изменения и настройки не стираются. Конфликт или разошедшаяся история требуют ручного решения.
4. Проверяет окружение и повторяет setup. Явно сохранённые настройки не должны заменяться
   без отдельного действия оператора. Если обновление остановилось после остановки сервисов,
   они не запускаются «на всякий случай».

Не подменяйте origin и не переносите маркер в другой каталог. Обычный `git clone` без
маркера — это checkout для разработки, а не установка, которую bootstrap вправе обновлять.

## Требования к железу и ограничения

Планируйте **16 ГБ RAM и SSD с 15–20 ГБ свободного места** для базовой установки;
32 ГБ RAM и NVIDIA GPU с 8 ГБ VRAM дают больше запаса для контекста и инструментов.
Это ориентиры для планирования, не гарантированный минимум: расход зависит от длины
контекста, runtime, модели, проекта и количества одновременно работающих инструментов.
CPU-путь функционален, но большие модели и длинные запросы могут быть медленными.
Не принимайте наличие маленького GGUF-файла за обещание низкого полного расхода RAM/VRAM.

Базовые языковые веса: 9B — около 2.68 ГБ, 4B — 1.27 ГБ, 2B — 0.52 ГБ.
`--with-security` добавляет примерно 4.68 ГБ. Дополнительно нужны runtime, Python,
зависимости Hermes, временные файлы и кэш. `fast` не является установкой только одной 2B-модели.
Визуальные проекторы не входят в базовый текстовый путь.

По умолчанию — до **50 логических задач**, максимум **два** одновременно декодирующих
воркера, до **64K токенов на слот**. Это не 50 копий весов и не обещание 50 параллельных
полноскоростных моделей. Native router держит одну резидентную модель и переключает роли;
очередь, переключения и KV/recurrent state влияют на задержку. Вход и резерв ответа
проверяются нативным шаблоном/токенизатором выбранной модели, без тихого усечения.
Фоновый sleep и самоизменение исходников в локальном профиле по умолчанию выключены.
Качество маленьких локальных моделей не равно качеству крупных облачных моделей.

## Запуск, остановка, интерфейс

Из каталога установки:

```bash
# Linux
.venv/bin/python -m local.manage start
.venv/bin/python -m local.manage status
.venv/bin/python -m local.manage stop
.venv/bin/python -m local.run_hermes
```

```powershell
# Windows
.\.venv\Scripts\python.exe -m local.manage start
.\.venv\Scripts\python.exe -m local.manage status
.\.venv\Scripts\python.exe -m local.manage stop
.\.venv\Scripts\python.exe -m local.run_hermes
```

Локальный API: `http://127.0.0.1:8775/v1`, модель-фасад `roi-swarm`.
Панель: `http://127.0.0.1:8775/dashboard`.
Нативный inference-сервис: `http://127.0.0.1:8091`.
При занятом порте установка/запуск должны отказать, а не завершать чужой процесс.
Логи и записи владения процессами находятся в `data/` установки. Для диагностики начните
с `local.manage status` и файлов в `data/diagnostics/`.

`local.run_hermes` запускает отдельный локальный Hermes с явным локальным провайдером.
Ваш активный desktop-профиль и его маршруты при этом не изменяются.
Для смены worker-профиля сначала остановите сервисы, затем выполните
`python -m local.profiles fast` или `balanced` **именно интерпретатором `.venv`** и запустите снова.
WhiteRabbitNeo не используется как Hermes tool-worker: это отдельный текстовый специалист.

## Права и безопасность

- API и inference слушают только loopback. По умолчанию локальный API может работать без
  bearer-токена: **loopback не является аутентификацией** против других процессов/пользователей
  на этом компьютере. Не публикуйте эти порты наружу и не делайте проброс без отдельного
  проектирования доступа. Код API поддерживает `ROI_SWARM_API_KEY`; управление токеном —
  отдельная настройка, не аргумент установщика. Не передавайте секреты в URL или командной строке.
- Hermes-инструменты работают с правами вашей учётной записи и могут выполнять команды,
  читать/записывать файлы и обращаться в сеть. Git worktree, локальный токен и разрешения
  инструментов **не являются OS sandbox**. Для недоверенных задач используйте отдельную
  непривилегированную учётную запись/машину и резервные копии.
- Локальный inference не означает, что инструменты автоматически работают без интернета:
  сетевые запросы возможны по задаче. Не передавайте недоверенной задаче доступ к секретам.
- Security-модель применяйте только к своим системам или при явно полученном разрешении.
  У неё отдельные условия использования; наличие `apache-2.0` в metadata конвертации
  не отменяет дополнительных ограничений исходного автора.

## Проверки и разработка

```bash
uv sync --frozen --extra dev --python 3.11
uv run --no-sync pytest -q
uv run --no-sync ruff check .
```

CI содержит app-тесты Linux Python 3.11/3.14 и Windows Python 3.11,
реальные bootstrap-прогоны в одноразовом offline Git/app fixture (на Windows — обычным,
не административным пользователем), ShellCheck и сканирование отслеживаемых файлов.
Fixture использует настоящий Git и uv, но **не выдаёт тестовый вывод за inference**.

Отдельный Ubuntu CPU job скачивает проверенные Prism CPU binary и Bonsai 2B и проверяет
реальную генерацию, native token accounting и структурированный tool-call. У него 4K-контекст
и один слот: это не нагрузочный тест полного роя, не тест 64K и не проверка CUDA.
Лог и `cpu-result.json` сохраняются как CI artifacts; статус конкретной ревизии смотрите
во вкладке [Actions](https://github.com/Andrylynev/roi-swarm-local/actions).
Наличие workflow в репозитории само по себе не означает, что все платформы уже прошли E2E.

Legacy cloud installer хранится только для регрессионных тестов и не является путём
установки этого локального клиента.
